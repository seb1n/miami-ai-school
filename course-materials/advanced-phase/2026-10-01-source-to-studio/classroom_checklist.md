# Classroom checklist

Use this alongside the student workbook. All example businesses and events are fictional.

## Build and review

- [ ] Read the source pack input and identify what is missing
- [ ] Draft the newsletter first and keep its evidence map
- [ ] Adapt the newsletter into LinkedIn and X drafts without adding facts
- [ ] Prepare four video scenes with supported on-screen text
- [ ] Render and play the actual draft MP4 through the host app
- [ ] If using the supplied sample, label the activity offline evaluation of that sample
- [ ] Have a person review each available artifact against the source
- [ ] Record the decision and exact artifact versions
- [ ] Hold approval for any missing or unseen media

## Evaluate after human review

- [ ] Define expected behavior before looking at the candidate result
- [ ] Use core cases 01, 02, 07, 08, 10 and 12 in pairs
- [ ] Distinguish executable checks, human content review and optional design exercises
- [ ] Keep exact checks, factual support and quality scores separate
- [ ] Give each result an output or log reference
- [ ] Mark missing evidence NOT RUN, not PASS
- [ ] Change one rule or guard and keep the test set unchanged
- [ ] Retain original and revised outputs
- [ ] Return changed content to human review

## Stay honest about the mode

- Authored-fixture replay uses prepared teaching content, not a captured successful API run
- The agent drafts text and scene specifications; the host app renders the video
- A sample video is not proof that revised text was rendered
- A fixture switch is not measured prompt improvement
- The separate ElevenLabs demo uses Harbor Bike Repair; it is not part of the content pipeline
- Approval and export do not publish anything

## Finish

- [ ] Source, outputs, review decision, tests and remaining blockers are included
- [ ] The final package status matches what was actually checked
- [ ] No API key, private source, real customer detail or unsupported action claim appears
