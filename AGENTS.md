# Miami AI School repository guidance

## Purpose

Maintain course materials, presentations, exercises, example code, and an index of standalone project repositories.

## Organization

- `course-materials/`: guides, workbooks, assignments, and session indexes.
- `presentations/`: editable decks and PDF exports.
- `code/`: independent runnable examples, each with its own README.
- `projects/`: links to separate application repositories.
- `resources/`: reference links and reusable templates.

## Working practices

Keep teaching material practical, clear, and appropriate to the session. Session 2 is the first build session and starts from an empty folder. Do not assume a prepared application exists.

Use plain English and no em dashes. Preserve the instructor's edits. Update relevant indexes when adding files. Keep links relative for repository content.

## Commands and verification

This is a materials repository with no root application or test command. Inspect each code example's README and manifest before running its commands. Do not invent commands or claim unrun checks passed.

For documentation changes, check spelling, links, filenames, and consistency with the session. For presentations, inspect rendered slides. For code, run checks appropriate to that example and report results and limitations.

## Boundaries

Always preserve unrelated work and identify the current version of materials.

Ask before changing repository visibility, publishing participant information, or adding paid external services unless already authorized.

Never commit credentials, private participant records, installed dependencies, or local environment values. Never describe generated or untested code as a verified classroom application.
